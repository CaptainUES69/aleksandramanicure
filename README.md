# Aleksandra Manicure: выдача доступа к курсам

Небольшой веб-сервис на FastAPI. Принимает вебхук с сайта (Tilda) о новой покупке и автоматически выдаёт покупателю доступ к курсу на платформе XL (Prodamus XL) через её API.

## Как это работает

```
Tilda (оплата) ──POST /this/is/buy──▶ FastAPI ──фоновая задача──▶ API XL
                                         │                         (поиск/создание контакта,
                                         └─ сразу отвечает 200 OK   запуск сценария выдачи курса)
```

1. После оплаты Tilda отправляет данные формы на `POST /this/is/buy`.
2. Сервер сразу отвечает `200 OK`, а обработка идёт в фоне.
3. По email ищется контакт в XL. Если его нет, он создаётся.
4. Запускается сценарий XL, который выдаёт нужный курс.
5. Тариф-апгрейд «Пилочный для тебя 2.0» выдаётся только тем, у кого курс «Пилочный для тебя» уже есть в библиотеке.

Результат каждой покупки (успех, пропуск, ошибка) пишется в логи.

## Запуск

### 1. Подготовка

В корне проекта (рядом с `Dockerfile`) создайте файл `.env`:

```env
PRODAMUS_TOKEN=ваш_токен_api_xl
```

Токен API берётся в личном кабинете XL (справка по API: https://app.xl.ru/api/public).

Убедитесь, что в `requirements.txt` есть:

```
fastapi
uvicorn
pydantic
python-dotenv
requests
```

> Код использует f-строки с вложенными кавычками, поэтому нужен Python 3.12+. В `Dockerfile` уже указан `python:3.12-slim`.

### 2. Сборка и запуск

```bash
docker compose build
docker compose up
```

Чтобы запустить в фоне, добавьте `-d`: `docker compose up -d`.

Сервер будет доступен на порту **8000**: `http://localhost:8000`

Интерактивная документация FastAPI: `http://localhost:8000/docs`

### 3. Проверка, что всё работает

Тестовый запрос (в XL ничего не отправляется):

```bash
curl -X POST http://localhost:8000/this/is/buy \
  -H "Content-Type: application/json" \
  -d '{"test": "hello"}'
```

Ожидаемый ответ:

```json
{"status": "OK", "message": "Test successful"}
```

### 4. Остановка

```bash
docker compose down
```

## Настройка Tilda

В настройках формы на Tilda (Контент → Webhook) укажите адрес:

```
https://<ваш-домен>/this/is/buy
```

Сервер должен быть доступен из интернета (домен или публичный IP, порт 8000 или reverse-proxy, например nginx).

## Логи

Логи лежат в папке `./logs` на хосте (она проброшена в контейнер через `docker-compose.yml`):

| Файл | Что пишет |
|------|-----------|
| `logs/webserver.log` | Все входящие запросы |
| `logs/methods.log` | Работа с XL: создан ли пользователь, запущен ли сценарий, ошибки |

Каждый файл ротируется при достижении 5 МБ, хранится до 5 копий.

Посмотреть логи вживую:

```bash
tail -f logs/methods.log
```

## Добавление нового курса

В `src/utility.py` добавьте новый элемент в `Courses`:

```python
NEW_COURSE = Course(
    tilda_name="Название товара на Tilda",  # должно точно совпадать
    XL_name="Название курса в XL",
    course_id=6,
)
```

`tilda_name` должно в точности совпадать с названием товара в заказе на Tilda, `XL_name` - с названием курса (библиотеки) в XL.

## Частые проблемы

| Проблема | Что проверить |
|----------|---------------|
| Ошибки авторизации от XL | Правильно ли указан `PRODAMUS_TOKEN` в `.env`. После изменения `.env` нужен `docker compose build` и перезапуск |
| Покупка пришла, а доступ не выдан | Смотрите `logs/methods.log`: там указана причина |
| `FileNotFoundError: ./logs/...` при запуске без Docker | Создайте папку `logs` в корне проекта: `mkdir logs` |
